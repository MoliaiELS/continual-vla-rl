# RoboTwin 2.0：50 个任务的源码目录

任务 ID 和顺序取自[官方 50 任务目录](https://robotwin-platform.github.io/doc/tasks/index.html)。逐项与 [RoboTwin 固定提交](https://github.com/RoboTwin-Platform/RoboTwin/commit/6e75b8b80ee32d2f495eb756cf5687e4e16f0eea) 的 [评测步数上限表](https://github.com/RoboTwin-Platform/RoboTwin/blob/6e75b8b80ee32d2f495eb756cf5687e4e16f0eea/task_config/_eval_step_limit.yml)及 [X‑VLA 固定 client 的 ALL_TASKS](https://github.com/2toinf/X-VLA/blob/6c4ecfb8be458ae7c0c96094e4b0add4174f4fe2/evaluation/robotwin-2.0/client.py#L38)比对，三个集合完全一致；全部 50 个 ID 均有独立的任务文件、专家脚本和成功判定。[机器可读目录](../../tools/xvla/robotwin/tasks.json)保留相同顺序、完整指令和对应代码行。

主类别是本项目按目标分析所得，每个任务归一类；抓取后保持悬空的任务也归入抓取搬运类。辅助标签以专家脚本为依据，可以重叠，不能当成独立成功判据。诸如敲击力度、扫描解码、订纸和摇晃历史，按锁定谓词实际检查的内容解释。

下表的“源码已核”只证明任务存在且已复查专家步骤与成功谓词。每个任务在 Easy／Hard 仍需分别验收：reset → RGB／proprio → 执行首个 X‑VLA 动作 → 调用官方成功谓词 → 完成正式回合。实际阶段与分母以作业结果为准。[RLinf 固定文档](https://github.com/RLinf/RLinf/blob/1bf78980d9339cbc67497eddceb9a1e3a74e2acc/docs/source-en/rst_source/examples/embodied/robotwin.rst)标注四项未支持，且仓库只随附 22 个任务的 eval seed 表；目录不会把 RLinf 默认配置或 seed 文件当作原生 runner 已通过的证据。

原生源码的四项注意点：

- `place_fan` 有完整官方专家脚本和成功谓词，无专家专属字段依赖，仍需运行验证。
- `open_laptop` 的成功谓词需要 `arm_tag`；专家按机身朝向推导该值。
- `place_object_scale` 的成功谓词需要 `arm_tag`；专家按物体初始 x 坐标决定执行臂。
- `put_object_cabinet` 的成功谓词需要 `arm_tag` 与 `origin_z`；专家按物体初始 x 选执行臂，并保存物体初始高度。
