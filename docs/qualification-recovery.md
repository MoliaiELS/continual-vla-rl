# 两任务回放资格验收恢复

2026-11-04，原 `20261104-qualification-v3` 的 Seq、Joint 已完成训练及阶段评估。Seq+ER 作业 19040 完成全部 4 个采集周期、16,384 个策略控制步并保存阶段 adapter，但在训练后的 BC 诊断要求处以非零退出。其第二任务的两个组均全败，按已声明的规则同时跳过 GRPO 和 BC；因此本次 Seq+ER 实际没有执行辅助回放。

这不构成 ER 有效性的证据，也不能把它归因于回放梯度错误、显存不足或新的优化器故障。原作业的 FAILED 状态和原始日志保留。

## 验收判定

每个训练运行仍要求完整的实际预算日志、最终 adapter 和隔离的非零 RL 梯度。ER 的额外状态分为：

| 状态 | 判据 | 解释 |
| --- | --- | --- |
| `verified` | 获准回放的阶段确有优化，BC 样本呈现非零，隔离梯度非零且阶段一致 | 已验证执行辅助回放 |
| `not_exercised` | 所有获准回放周期均因无有效组而跳过 GRPO 和 BC，实际 BC 呈现为零 | 流程运行完成，但未执行回放 |
| 验收失败 | 有回放资格且发生优化，却缺少 BC 梯度或准入记录不一致 | 实现或证据不足，阻断后继 |

整个资格 suite 仍要求至少一个 ER 运行存在隔离的非零 BC 梯度。Joint+ER 从开始就获准访问两个训练任务的记忆，可在 task 0 的有效组上完成该检查。不能仅将所有 ER 运行标为未执行后直接通过资格 gate。

## 复用原始结果

新增 `experiment.py recover` 创建新的只读来源派生计划，不覆盖旧 plan、日志或 checkpoint，也不声称实现了优化器/RNG 断点恢复。

恢复时检查模型与任务协议保持不变，并通过 Git diff 要求训练、环境、模型、算法与评估代码均无变化。成功任务的 job/result/commit 身份、已完成评估的 episode 数，以及训练的完整预算、梯度与阶段权重都重新核实。保留结果记录来源 commit、原作业 ID、文件大小和 SHA256。

只有明确出现原 BC 验收错误、同时又有完整训练闭环及 `not_exercised` 证据的失败运行，才允许按“训练完成、旧 gate 未通过”复用。其他失败或不完整训练需要新的独立尝试，已消耗预算继续单列。

原始 v3 可复用 Seq、Joint 与 Seq+ER 的三次完整训练、已有阶段评估及基座/仿真检查。剩余执行顺序为：

1. Seq+ER 两个阶段的独立评估，使用原来已保存的 adapter。
2. 新的 Joint+ER 资格训练及两个阶段评估。
3. 相机和 Object 开发任务的基座评估。
4. 总资格 gate 与结果绘图；通过后才启动新的五任务与十任务计划。

这会生成 8 个剩余作业，只新增 Joint+ER 的 16,384 个训练控制步。旧 Seq+ER 的零 BC 呈现必须在报告中标注；其结果不能用于声称“ER 提升/损害了保持能力”。

## CLI

在由本项目远程入口初始化的、已提交版本 worktree 中：

```text
python tools/idac/experiment.py recover <新资格目录> --source-suite <原资格目录> --commit <新代码完整commit> --next-suite <新五任务目录>
python tools/idac/experiment.py submit <新资格目录>
```

恢复计划仍是 `profile=qualification`，采用原来的模型、预算、初态、方法和种子。新五任务与十任务目录使用同一新代码 commit；原始未启动计划保留，不进行原地改写。
